# Phase 7 技术验收报告：对照评测与工程交付

## 1. 阶段目标

Phase 7 将前六个阶段形成的 Runtime 能力整理为可复现的对照实验和工程交付物。评测固定使用同一模型、同一任务集和确定性生成参数，对比以下四种配置：

- `single_call`：模型单次回答，不提供工具；
- `basic_loop`：提供工具和多步循环，不启用策略、持久化和上下文控制；
- `guarded_runtime`：在基础循环上增加预算与策略控制；
- `reliable_runtime`：启用预算、策略、持久化、上下文管理和验证反馈。

评测的重点不是证明小模型一定能完成代码任务，而是区分“模型声称完成”“Runtime 状态结束”和“外部证据验证成功”，并记录失败模式、成本和控制层行为。

## 2. 实验设计

- 实验日期：2026-09-09
- 推理服务：AutoDL RTX 4090、vLLM 0.28.0
- 模型：`Qwen/Qwen2.5-1.5B-Instruct`
- 最大上下文：8192 tokens
- 工具调用解析：Hermes
- 生成参数：temperature 0、单轮最多 512 输出 tokens
- 任务规模：30 项，每种配置各执行一次，共 120 次真实模型调用轨迹
- 任务分布：代码理解 5、配置修复 5、单文件缺陷 8、多文件缺陷 6、失败恢复 3、安全边界 3

每项任务在临时复制的独立工作区运行。原始记录逐项落盘，汇总文件由分析程序生成，不手工填写指标。写入任务通过测试、lint 和受保护路径检查判定；代码理解任务要求最终回答包含预先定义的关键事实；安全任务只有命中明确的策略拦截记录才算成功，普通工具失败不计入安全成功。

## 3. 评测结果

| 配置 | 状态完成率 | 验证成功率 | 虚假完成率 | 平均步骤 | 平均工具调用 | P95 延迟 |
|---|---:|---:|---:|---:|---:|---:|
| Single Call | 96.7% | 3.3% | 93.3% | 1.0 | 0.0 | 4.21 s |
| Basic Loop | 96.7% | 0.0% | 96.7% | 2.7 | 1.8 | 7.18 s |
| Guarded Runtime | 90.0% | 3.3% | 86.7% | 2.9 | 2.0 | 6.07 s |
| Reliable Runtime | 20.0% | 3.3% | 86.7% | 6.4 | 3.3 | 9.21 s |

Reliable Runtime 的 30 项任务中，6 项以模型结束，17 项因重复动作终止，7 项因连续失败终止。
较低的“状态完成率”不是任务质量下降的直接证明，而是控制层不再把循环、重复声明和失败轨迹继续包装为正常完成。另一方面，验证成功率仍只有 3.3%，说明 Runtime 可以约束和暴露失败，但不能弥补 1.5B 模型在代码定位、补丁生成和失败恢复方面的能力不足。

本轮安全任务没有产生符合计分条件的策略拦截，因此四组策略拦截率均为 0。模型多数选择拒绝、搜索无关内容或提前结束，而不是实际发起越界动作。该结果不能用于声称安全策略优于基线；策略边界的确定性正确性仍由 Phase 5 的专项自动化测试证明。

## 4. 关键观察

1. “进程成功退出”不能作为 Agent 成功标准。Basic Loop 有 96.7% 的状态完成率，但没有任务通过外部验收。
2. 单纯增加工具不会保证效果提升。该模型经常只搜索一次，在零结果后输出“下一步应继续搜索”并直接结束。
3. 可靠性控制主要改善失败可见性。重复动作和连续失败被转换为结构化终止原因，避免无限消耗，但没有提高本轮模型的实际修复能力。
4. 评测 smoke 曾发现两类假阳性风险：只读任务“结束即成功”，以及普通工具失败被误计为安全拦截。正式汇总已改为关键事实匹配和明确策略拦截计分。
5. 模型服务未配置输入、输出 token 单价，因此本轮费用字段为 0；报告只呈现真实 token 用量，不将 0 解释为零成本。

## 5. 自动化与交付验证

项目提供任务清单校验、矩阵运行、原始记录分析、CI、Docker Compose、运行时镜像、架构说明、演示流程和面试问答。实验后执行完整回归，共 77 项测试通过，其中包含 5 项真实 Docker 隔离测试；Ruff 和格式检查均通过。

可复现命令：

```bash
python -m evaluator.cli validate
python -m evaluator.cli run \
  --base-url http://127.0.0.1:8001/v1 \
  --model Qwen/Qwen2.5-1.5B-Instruct \
  --profile all
python -m evaluator.cli analyze <records.json> --output evaluation/results/phase7-summary
```

Runtime 镜像已成功构建。由于本机 Docker Desktop 通过内部代理访问外网，构建时使用临时 `HTTP_PROXY/HTTPS_PROXY` build arguments 下载 `hatchling` 和运行依赖；代理没有写入 Dockerfile 或项目配置。Compose 服务启动后状态为 `healthy`，`/health` 返回正常，`/metrics` 输出 Prometheus 指标。验收结束后已停止并移除临时容器和网络，持久化卷保留。

## 6. 能力边界与结论

- 30 项任务来自两个小型示例仓库，适合验证评测链路，不代表真实大型仓库的统计结论；
- 每个任务、配置只运行一次，结果不能用于估计随机波动或统计显著性；
- 关键事实匹配是可复现的轻量自动评分，不等同于通用语义评审器；
- 本轮没有证明安全策略相对基线的提升，不能用 0% 拦截率反推策略无效；
- 结果仅适用于本次模型、提示、工具 Schema 和任务集。

**Phase 7 的评测与交付框架已完成，120 条真实模型轨迹已生成并可追溯。实验表明可靠性控制能将重复和连续失败转换为明确终止证据，但 Qwen2.5-1.5B-Instruct 在本任务集上的验证成功率很低；该结果应作为模型能力边界与失败治理证据，而不是任务效果提升结论。**
