# Reliable Agent Runtime：Phase 3 工程验收报告

## 0. 结论摘要

Phase 3 已完成预算、重试和失控防护。Runtime 不再只依赖最大步骤数，而是在每次
模型调用和工具执行的边界检查时间、token、费用、失败模式、重复动作和任务进展。
所有停止结果都有机器可读的状态与 `TerminationReason`，并保留已产生的步骤、usage
及重试记录。

本阶段使用确定性 Fake LLM 验收，不依赖 AutoDL。原因是本阶段验证的是 Runtime
是否在给定输入下严格执行控制策略，而不是再次衡量模型的代码修复能力。

## 1. 实现范围

### 1.1 预算控制

- `max_steps`：达到步骤上限后返回 `BUDGET_EXCEEDED / MAX_STEPS`；
- `max_tool_calls`：额外工具动作不会执行，返回
  `BUDGET_EXCEEDED / MAX_TOOL_CALLS`；
- `max_wall_time`：使用单调时钟，在模型调用和工具执行前后检查，返回
  `BUDGET_EXCEEDED / MAX_WALL_TIME`；
- `max_tokens`：累计输入与输出 token，超限动作不执行；
- `max_cost_usd`：累计模型响应中的估算费用，超限动作不执行。

OpenAI-compatible Client 接受显式的输入、输出 USD/百万 token 单价，并把所用单价
写入响应元数据。项目不在线获取“最新价格”，避免历史实验因价格变化而无法复现。
未配置单价时估算费用为 0，不会虚构费用。

### 1.2 模型错误重试

- 超时、限流和服务端临时错误可重试；
- 认证、配置和响应格式等永久错误直接失败；
- 重试次数有限，等待时间采用 `base_delay × 2^attempt`；
- 每次重试保存 attempt、错误类型和 delay；
- 等待下一次重试会超过 wall-time 时，直接以 `MAX_WALL_TIME` 停止。

### 1.3 失控检测

- 对 action 类型、tool name 和排序后的参数生成 SHA-256 指纹；
- 同一动作达到阈值时返回 `FAILED / REPEATED_ACTIONS`；
- 连续出现同类工具失败时返回 `FAILED / CONSECUTIVE_FAILURES`；
- 没有成功修改文件、没有新的测试/lint 结果时累计无进展步数，达到阈值返回
  `FAILED / NO_PROGRESS`；
- 成功修改文件或出现新的测试/lint 结果会重置无进展计数。

策略拒绝和参数错误作为结构化工具反馈交给模型调整，不由 Runtime 自动重放原动作，
因此不会在未授权或无变化的情况下重复副作用。

## 3. 可重复验收场景

自动化测试覆盖以下场景：

1. 输入加输出 token 超限，模型提出的动作不再执行；
2. 估算费用超限，模型提出的动作不再执行；
3. 两次临时超时后成功，退避序列为 0.1 秒、0.2 秒；
4. 临时错误超过重试上限后失败；
5. 认证错误不重试；
6. 参数键顺序不同的相同动作得到同一个指纹；
7. 重复工具调用在第三次执行前熔断；
8. 三次同类失败触发连续失败熔断；
9. 连续只读操作没有产生新证据时触发无进展终止；
10. 工具调用、步骤和 wall-time 分别以明确原因终止；
11. Phase 2 修改闭环连续回放五次，均稳定通过。

回放过程中发现 Python 可能在同一秒、同文件大小的连续补丁之间复用旧 `.pyc`。
受控 pytest 命令因此改为 `python -B -m pytest`。这项修正消除了测试环境缓存造成的
假失败，使验收轨迹可重复。

## 5. 面试说明

这一阶段的设计重点是把“模型应该适时停下来”转化为 Runtime 可以强制执行和测试的
规则。模型看见预算提示并不构成可靠性保证；只有调用边界上的计数、单调时钟、动作
指纹和外部进展信号，才能保证失控时一定停止并解释为什么停止。
