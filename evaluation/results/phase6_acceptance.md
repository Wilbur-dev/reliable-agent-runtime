# Phase 6 技术验收报告：上下文管理与可观测性

## 1. 阶段目标与结论

随着 Agent 连续执行工具，完整历史会持续增长。如果每轮都把全部轨迹重新发送给模型，调用成本和延迟会不断上升，大型测试日志还会挤占真正影响下一步决策的信息。另一方面，直接删除早期历史可能丢失任务约束、失败证据或已完成操作，导致重复修改和错误决策。

Phase 6 将“数据库中的完整执行事实”与“当前模型所需上下文”分为两层：SQLite 保留完整轨迹，Context Builder 在每次模型调用前构造有界视图。同时增加结构化事件和 Prometheus指标，使压缩过程、调用成本和失败原因能够被查询和解释。

## 2. 上下文管理设计

### 2.1 分层上下文

- 系统规则、用户目标、约束和验收条件始终保留；
- 最近若干条动作与观察保留完整结构；
- 较早历史压缩为包含工具、结果、错误类型、修改路径和结果引用的结构化摘要；
- 压缩只影响发送给模型的视图，不覆盖数据库中的原始消息和步骤；
- 压缩阈值、近期消息数量、工具输出长度和摘要长度均可按任务配置。

### 2.2 大型输出引用

大型测试日志不会完整进入 Prompt。模型侧只看到关键头尾及 SHA-256 `result_id`，完整输出仍保存在步骤结果中，可通过 `GET /tasks/{id}/results/{result_id}` 查询。这既降低上下文占用，也保留了复盘和审计所需的原始证据。

### 2.3 文件版本识别

`read_file` 在返回内容时记录文件哈希。Context Builder 构建下一轮输入时会校验当前文件；若文件已经变化，旧观察会被标记为 stale，并提示 Agent 重新读取，避免补丁之后继续引用旧版代码。

### 2.4 压缩证据

每次触发压缩都会持久化：触发步骤、压缩消息数量、压缩前后字符数、压缩前后估算 token、结构化摘要、输出引用以及失效文件引用。任务汇总同时记录累计压缩次数和最近一次压缩前后token 数。

## 3. 可观测性设计

Runtime 记录以下结构化事件：

- `model_finished`：模型延迟、输入/输出 token 和估算费用；
- `model_retry`：错误类型、重试次数和退避时间；
- `tool_finished`：工具名、结果、错误、退出码和工具延迟；
- `policy_decision`：策略结论、命中规则和目标工具；
- `context_compacted`：压缩前后 token、摘要规模和引用信息；
- `task_finished`：最终状态、终止原因、耗时和累计资源使用。

事件同时写入 SQLite 和 JSON 日志。HTTP `/metrics` 提供 Prometheus 文本格式指标，覆盖任务状态、任务耗时、工具调用与错误、模型 token、预算终止、验证失败和上下文压缩次数。

## 4. 自动化验收证据

- 验收日期：2026-09-09
- 运行基线：Python 3.11、SQLite、Prometheus client、Docker Engine 25.0.2
- 验证方式：Fake LLM 确定性长轨迹、API 集成测试和真实 Docker 隔离回归
- 模型依赖：无。Phase 6 验证的是 Runtime 上下文控制和观测行为，不衡量模型生成质量。

复现命令：

```bash
python -m ruff check .
python -m ruff format --check .
python -m pytest -q
```

最终结果：

```text

```

关键验收场景：

- 长任务产生 8 次大文件读取并最终完成，证明压缩不会中断执行闭环；
- 每次压缩后的模型输入估算 token 均小于压缩前，固定目标、约束和验收条件仍保留；
- 数据库仍保存 9 个完整步骤及未经 Prompt 裁剪的工具输出；
- `result_id` 能查询并校验对应完整输出的 SHA-256；
- 文件修改后旧读取观察被标记失效；
- API 可查询压缩记录和运行事件，Prometheus 端点包含任务、工具和压缩指标；
- Phase 0—Phase 5 的既有测试全部通过。

测试仅出现 FastAPI `TestClient` 关于未来 `httpx2` 迁移的上游弃用警告，不影响结果。

## 5. 能力边界

- token 数采用稳定的字符数近似，适合比较压缩前后变化；真实模型计费仍以供应商 usage 为准；
- 当前摘要由确定性规则生成，不使用额外模型，优点是可复现且无额外成本，缺点是语义密度低于专用摘要模型；
- Prometheus 指标保存在当前服务进程内，生产环境需要独立采集、持久化和多实例聚合；
- 输出引用使用内容哈希定位已有步骤结果，不是通用对象存储；
- 上下文压缩降低成本和过长输入风险，但不保证模型一定正确使用保留下来的信息。

## 6. 验收结论

**Phase 6 通过。系统已经区分完整事实轨迹与有界模型上下文，并对压缩、模型调用、工具执行、策略决策和任务结果提供可查询的结构化证据与 Prometheus 指标。**
